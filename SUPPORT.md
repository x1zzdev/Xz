# Support

## Where to ask

| Need | Where |
|---|---|
| A usage question or an open-ended idea | [GitHub Discussions](https://github.com/x1zzdev/Xz/discussions) |
| A confirmed bug or a concrete feature request | [Issues](https://github.com/x1zzdev/Xz/issues) |
| A security problem | [SECURITY.md](SECURITY.md), privately |
| A contribution workflow question | [CONTRIBUTING.md](CONTRIBUTING.md) |

Discussions is the right place for "how do I" and "what if" questions. The issue tracker is for things that can be closed with a commit.

## Before you ask

- Read [README.md](README.md) and the relevant document in `docs/`. The specification answers most design questions directly.
- Search open and closed issues. The problem may already be known.
- For a bug, prepare a minimal `.xz` file and the exact command you ran.

## What to expect

Xz is maintained by a small number of people. Questions usually get a reply within a few days. Feature requests are read, but not every one is accepted: the [philosophy](docs/01-philosophy.md) is the filter, and a feature that makes the language harder to review is declined even when it is popular.

## Commercial support

There is none. Xz is a community project with no support contracts, no SLAs, and no paid tier.
